# VENATOR PERFORMANCE LAB

Русскоязычное локальное веб-приложение для осознанной практики на Venator в Deadlock. React + TypeScript + Vite + Tailwind CSS, Recharts и Lucide React. Без сервера, регистрации, платных API и передачи статистики третьим лицам.

## Быстрый запуск

Нужен Node.js 22 или новее.

```bash
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Для проверки production-версии:

```bash
npm test
npm run build
npm run preview
```

Не открывайте `index.html` двойным щелчком: ES-модулям и PWA нужен HTTP/HTTPS.

## Публикация на GitHub Pages

1. Создайте репозиторий, например `venator-performance-lab`.
2. Распакуйте архив. Загрузите **содержимое** папки проекта в корень репозитория, включая `.github/workflows/pages.yml`, `package.json` и `package-lock.json`. Не загружайте `node_modules`.
3. В GitHub откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Отправьте файлы в ветку `main`. Workflow проверит тесты, соберёт приложение и развернёт Pages. При необходимости запустите его вручную через вкладку Actions.
5. Дождитесь зелёного статуса и откройте URL из результата deployment. Обычно это `https://USERNAME.github.io/venator-performance-lab/`.

Workflow берёт `base_path` из `actions/configure-pages`: работает и для сайта репозитория, и для корневого сайта / собственного домена. Локальная сборка по умолчанию использует относительный `base: './'`. Пример ручной сборки на Linux/macOS:

```bash
BASE_PATH=/venator-performance-lab/ npm run build
```

В PowerShell: `$env:BASE_PATH='/venator-performance-lab/'; npm run build`.

Маршрутизация — переключение разделов внутри одной страницы: серверный fallback и файл 404 не нужны. Публичный сайт не публикует ваши матчи: каждый посетитель видит собственное локальное хранилище. В этой поставке нет созданного GitHub-репозитория или опубликованного URL: для этого нужен ваш репозиторий.

## Первый сеанс

1. Нажмите «Открыть деморежим», чтобы изучить интерфейс на 84 явно помеченных тестовых матчах.
2. Выйдите из деморежима: ваш личный журнал остаётся отдельным.
3. В настройках задайте свои цели и веса. Начальные числа — иллюстрация, не нормы игры и не бенчмарки ранга.
4. Введите 5–10 матчей. По их базовой линии откалибруйте цели.
5. Начните одну тренировку на 3–5 новых матчей. После блока оцените исполнение и выберите следующий фокус.
6. Регулярно скачивайте JSON, особенно перед очисткой браузера и сменой устройства.

## Продуктовая методика

Главный цикл: матч → короткий разбор → повторяющаяся проблема → одно проверяемое действие → тренировочный блок. Победа показывается отдельно от индивидуального качества. Рекомендуется добавлять метку патча и сравнивать одинаковые версии игры; изменение баланса может имитировать личный рост.

### Минимальный ввод

Дата/время, победа или поражение, длительность в минутах, убийства/смерти/ассисты, души, урон героям, результат линии, билд и главная ошибка (доступно «Нет явной ошибки»). Урон объектам необязателен: неизвестное значение оставьте пустым. 30:30 вводится как 30.5 минуты.

Расширенный ввод: соперник, предметы с минутой покупки свободным текстом, причины смертей, название ключевой способности, оценки применения способности/позиционирования/решений/концентрации/командных действий, несколько ошибок, заметки. Оценки 1–5 и контроль линии помечены как самооценки. Их не следует трактовать как точное измерение мастерства. Выполнение цели можно оставить неоценённым.

### Формулы

- KDA матча: `(K + A) / max(D, 1)`. На панели — арифметическое среднее KDA матчей, отдельно средние K, D, A.
- Души/мин, урон героям/мин, урон объектам/мин: значение / длительность каждого матча, затем среднее этих скоростей. Каждый матч имеет одинаковый вес, независимо от длительности.
- Смерти/10 мин: `10 × смерти / длительность`.
- Win Rate: `100 × победы / матчи`. В пустой выборке показано отсутствие данных.
- Нормализация «больше лучше»: `min(100, max(0, 100 × значение / цель))`.
- Нормализация смертей: `min(100, 100 × цель / значение)`; при нуле смертей — 100.
- Performance Score: сумма `нормализованный балл × вес` / сумма весов доступных категорий. Категории: экономика, реализация урона, выживаемость, объекты. Победа и самооценки не входят. Это выбранная пользователем модель, не официальный рейтинг или доказанная модель мастерства. При достижении целей значения насыщаются на 100; для анализа сверх цели смотрите исходные метрики.
- Полнота: доступный вес / весь вес. Нет доступных весов — нет балла. Неизвестные объекты исключаются; известный нулевой урон даёт 0 соответствующей категории. Подробный вклад каждого показателя открыт в форме матча.
- Низкая достоверность: меньше 5 матчей или полнота менее 80%. Порог — понятная эвристика, не доверительный интервал.
- Стабильность: `max(0, 100 − 2 × σ)` баллов, где σ — стандартное отклонение по выбранной совокупности баллов (деление на n). Требует 5 баллов. Стабильно низкая игра тоже может давать высокую стабильность. Различная полнота и насыщение шкалы ограничивают интерпретацию.
- Относительное изменение: `100 × (текущее − предыдущее) / abs(предыдущее)`. Нулевая база не даёт бесконечного процента. Для WR — процентные пункты; для Score и стабильности — баллы.
- Календарь: фактический месяц на 28–31 день. Цвет = `50 + (средний балл − 50) × n/(n+4)`. Сглаживание уменьшает влияние одного матча, но не является статистической оценкой уверенности. Нет матчей — нет оценки. Галочка означает наличие хотя бы одного матча с отмеченной целью, не выполнение всего блока.
- Частота ошибки: матчи с ошибкой / все матчи. Сравнение побед с ошибкой и без неё — ассоциация, не причинный вывод.

Даты хранятся с часовым поясом, отображаются по локальному времени браузера. При смене часового пояса матч может перейти в другой календарный день. Предыдущий период имеет одинаковое число календарных дней; текущий день бывает неполным. Динамика 5/10 матчей и 7/30 дней использует весь журнал с фильтрами билда и патча. Календарь использует собственный выбранный месяц. Сравнение билдов использует диапазон и патч, игнорируя фильтр одного билда.

### Правила рекомендаций

Используются последние 10 матчей личного журнала, независимо от фильтров панели:

1. Менее 5 матчей: собрать базовую линию и делать разбор.
2. Смерти/10 мин выше цели: целевое значение `max(ваша цель, среднее × 0.9)`.
3. Души/мин ниже цели: целевое значение `min(ваша цель, среднее × 1.1)`.
4. Иначе: разобрать самую частую отмеченную ошибку; при отсутствии ошибок — закреплять дисциплину.

Тренировка фиксирует критерий, исходное значение и время старта. Уже существующие матчи исключаются; берутся первые 3–5 новых матчей по времени. Прогресс блока — сыгранные / запланированные. Выполнение — успешные / оценённые. Неоценённые матчи не превращаются в неудачи. Самооценочные цели требуют ручной отметки; объективные проверяются формулой. Завершённые/остановленные цели остаются в истории; исправления и удаления матчей пересчитывают их итог. Изменение глобальных целей пересчитывает весь Score одной шкалой, но не меняет критерий уже созданной тренировки.

## Данные и восстановление

Версия документа: `version: 1`; ключ `venator-lab-v1`, демо — `venator-lab-v1-demo`. На чтении и записи проверяется полная схема, конечные и допустимые числа, диапазоны, ссылки билдов, уникальные идентификаторы и главная ошибка. Неизвестные версии отклоняются; при будущих версиях нужен явный адаптер миграции перед валидацией — неизвестные данные не интерпретируются молча.

Перед каждой обычной записью предыдущая валидная версия сохраняется в ключ `-backup`. Если запись не удалась, интерфейс не показывает её как сохранённую. Повреждённое хранилище блокирует обычную запись; настройки позволяют скачать исходные данные и восстановить JSON или предыдущую версию. Перед импортом/восстановлением скачивается текущая копия; исходная строка дополнительно сохраняется в ключ `-recovery`. Последовательная замена с подтверждением, не слияние. Максимальный размер импорта — 20 МБ; реально доступный объём localStorage зависит от браузера и часто значительно меньше.

CSV: UTF-8 с BOM, все поля заключены в кавычки, кавычки удваиваются, потенциальные формулы обезвреживаются префиксом `'`. CSV содержит все поля матчей, но не настройки и историю целей. Для переноса между устройствами используйте JSON.

Работайте в одной вкладке: автоматическое разрешение конфликтов одновременного редактирования не реализовано. Данные одного браузера не синхронизируются с другим; HTTPS-домен, протокол и порт определяют отдельное хранилище. Инкогнито, удаление данных сайта и смена домена могут сделать журнал недоступным. Резервная копия внутри браузера не защищает от его очистки — скачивайте JSON.

## PWA

Manifest, значки 192/512 и service worker включены. Во время сборки в offline-кэш добавляются конкретные хешированные JS/CSS-ресурсы. При первом успешном посещении по HTTPS дождитесь завершения загрузки и установки worker. После этого оболочка доступна без сети. Установка через меню браузера зависит от поддержки браузера. При новой сборке меняется версия кэша; новый worker активируется после закрытия старых вкладок. Хранилище матчей при этом не очищается.

## Проверка качества

Автоматические проверки: математические формулы, крайние случаи, пропуски, равные периоды, JSON round-trip, битые данные, ссылки билдов, веса, CSV, резервирование, правила тренировок; рендер всех основных страниц с пустыми и демонстрационными данными. TypeScript в strict-режиме и production-сборка.

Браузерная визуальная и интерактивная проверка в среде разработки была заблокирована политикой доступа к адресу предпросмотра. Поэтому установка PWA, автономный режим, загрузка файлов и мобильная раскладка не заявляются как проверенные end-to-end. Перед активным использованием выполните сценарии ниже.

1. Добавить матч, обновить страницу, проверить сохранение; изменить и удалить матч, восстановить резервную версию.
2. Экспортировать JSON, импортировать его, сравнить количество матчей; попытаться импортировать повреждённый JSON — данные должны сохраниться.
3. Включить демо, изменить тестовый матч, выйти: личный журнал не должен меняться.
4. На 375 px и на десктопе проверить навигацию и форму; Tab проходит поля, Escape закрывает диалог.
5. На опубликованном Pages открыть сайт, затем проверить перезагрузку без сети и установку через меню браузера.
6. Начать цель, добавить 3–5 матчей с временем после старта, завершить блок; проверить историю.

Приложение использует семантические кнопки, подписи полей, modal dialog, видимый фокус, текстовые обозначения исходов и поддержку reduced motion. Ни наличие цвета, ни график не являются единственным способом прочитать результат.
